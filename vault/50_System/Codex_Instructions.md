# Memory Policy

Use project memory only after explicit activation. Resolve the workspace and
read the active manifest first. Keep reads small and follow direct links.

Store current facts, decisions and useful next steps. Keep secrets, prompts,
transcripts and full logs out of the Vault. Project memory does not grant
permission to change an application or contact a remote service.

Update current state when verified evidence changes. Keep history in dated
notes. Preserve useful evidence. Use one writer per note and revision checks
before replacement. Local locks do not protect against an editor that ignores them.

Write a compact daily entry for each task in an active project. Use the session
helper. Validate changed notes and refresh generated indexes after route changes.
Run a full audit after broad changes. A clean audit does not prove factual truth.

Set `last_verified` only after a semantic review. Keep the zero-debt audit baseline.
The installed skill contains commands. The system manifest defines the schema.
